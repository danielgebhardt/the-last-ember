# Exit-dungeon scrolls — #324

> Historical review of #324. Superseded by the single-use town portal in #354; see [current town rules](town-rules.md). Historical save versions described below are retired under the [save policy](save-policy.md).

Select an Exit dungeon scroll stack in Character and choose **Read exit scroll**. One physical copy and one normal turn return the player to floor 1 beside the dungeon entrance. Successful reading closes Character and restores map focus; fatal arrival responses keep defeat ownership. Potions/spell hotbars are unchanged. The shared icon is a blue scroll with an upward arrow, used in map, bag and catalog.

`ExitDungeonScroll.ts` owns a pure arrival query and the domain effect behind `exit-dungeon`. It validates actual owned kind/ID, alive/non-victorious state and ember possession. The UI disables reading with an accessible ember explanation; the domain independently rejects it, including restored adventures. Already orthogonally adjacent on floor 1 is a free no-op. Other floor-1 positions can use the scroll. Arrival uses fixed north/east/south/west order, inspecting exactly four entrance neighbors. Walls, stairs, all objects (including spent ones), floor items and living creatures exclude a tile. There is no distant fallback or overwritten actor/content. If none qualify, the scroll and turn remain owned.

The existing action boundary commits the effect, then runs one normal arrival-floor monster/effect/recovery phase and updates discovery through the existing session. Departure-floor actors/effects stay frozen. Existing floor-1 threats can attack; player poison can kill. A completed teleport and consumption remain committed even after a fatal response. No intermediate floor phases, entrance victory, escape-wave activation, restock, free heal or resource refill is added. Ordinary turn-30 mana recovery and global player conditions still apply once.

`ExitScrollPlacement.ts` gives each floor from 2 onward a 15% chance of one safe room find, using a dedicated seed/floor stream. It avoids actors, protected stair/start locations and existing loot/books. Adding scrolls does not draw from ordinary loot or spellbook selection streams; later object placement respects the new occupied tile. This is a tuning default, not a guarantee that a particular seed contains a scroll. Scrolls are excluded from ordinary loot/drops and current merchant sale/purchase rules. Town scroll-shop #335 can define prices later; no merchant inventory contract is changed here.

V21 explicitly admits scroll ownership and `exit-scroll-used` history. Shape validation checks the new event, adapting only its validation view to the existing floor-change contract; the real history is retained. Source dispatch rejects scroll ownership/history declared under old versions. V1–v20 inputs still pass their source rules before migration; v20→v21 changes only the version marker. Existing actual geometry, actors, resources, inventory, depletion and exploration remain authoritative, with no scroll injection. New imports reject unknown kinds, duplicate IDs, enchanted scrolls, malformed/out-of-run origins and forged historical ownership. The confirmed save/export writer now emits v21; the local slot is not rewritten merely by loading.

Verification covers deterministic/fallback and blocked arrivals, floor-1 and deep use, wrong/missing copies, ended games, ember rejection, stack position, one enemy phase, frozen departure effects, poison/recovery and fatal ownership. Save tests round-trip new copies/events, preserve old played state and compare subsequent deterministic actions. UI/browser checks exercise real reading, remaining stack position, free repeat rejection, map focus, restored ember disabling and mobile overflow. Appearance/default frequency and human gameplay usefulness remain subject to developer review.
